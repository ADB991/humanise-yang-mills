This audit proposes *mathematical* handoffs. It does not translate the proofs. ## Quantifier and data contract

For a public `g : YangMills.GaugeGroup` with `g.IsSimple`, the bridge `YangMills.GaugeGroup.coreSimple` in `Lean/WilsonBridge.lean` supplies `g.core.Simple` for the internal `YM.Gauge`. At any `b>0`, `YM.Independent.constructionRun` and `YM.Independent.fundedRun` in `Lean/YM/Independent/ConstructionRun.lean` select an internal `R : YM.PhysicalNext.Repeat.Legato.Run g.core` **before** an extraction order is supplied. `YM.Nonperturbative.continuum_with_position_tests` (`Lean/YM/Nonperturbative/Continuum.lean`) then has the form

`R` fixed; for every `p : YM.Extraction.Order`, there exist `q, S, F, L, Q, M` (and later `X`) on `p.refine q` satisfying one joint receipt.

Here `YM.Extraction.Order` has independently increasing mesh and period sequences. `refine` composes *both* sequences (`Lean/YM/Extraction/Orders.lean`). The public `YangMills.JointExistence` (`Lean/ChallengeSpec.lean`) asks only for every increasing **period** sequence `p : ℕ → ℕ`; `YangMills.jointExistence` (`Lean/Solution.lean`) uses the full mesh sequence internally and returns `q.per`. It chooses one `WilsonFamily` before the requested `p`, then a hierarchy after `p`. Neither `S` nor `F` nor the phase space is asserted to be common to all requested sequences. The public theorem uses `b=1`, while `YangMills.constructed` (`Lean/Construction.lean`) retains any positive `b` and additional internal conclusions.

**Two orders.** The joint receipts state two different ordered limits. In `YangMills.constructed` (`Lean/Construction.lean`, the conjunct at line 23), `YM.R2IGoals.Broad.refine` and `YM.Nonperturbative.continuum_with_position_tests`, the displayed Wilson clause is `{ mesh := .full, per := (p.refine q).per }.Ordered C S`: the **full** mesh sequence at the refined periods. The final structure `F : YM.Spec.Final C (p.refine q) S` is indexed by the refined order, whose mesh component is `p.mesh ∘ q.mesh` (`Order.refine` composes both components, `Lean/YM/Extraction/Orders.lean`), and contains `F.room.ordered : (p.refine q).Ordered C S`; in `YangMills.jointExistence`, where `p.mesh` is the identity, this mesh component is `q.mesh`. The public `Properties` takes a period sequence only; its clause `wilson` is `WilsonFamily.Converges ((p.refine q).per) …`, which demands the full mesh limit at every suitable period, and `YangMills.wilsonLimit` (`Lean/HierarchyBridge.lean` 44–56) obtains it from the full-mesh `Ordered` conjunct, not from `F.room.ordered`. So full-mesh Wilson convergence and refined-mesh field extraction are distinct outputs, and the checkable PU-16 output for the public endpoint is the full-mesh statement. The full-mesh output is **derived**, rather than a second independent compactness extraction: `YM.FullVolume.Final.from_spec` (`Lean/YM/FullVolume/Finale/Program.lean` 117–126) combines `F.room.ordered` with PU-15's `PositionsUV R.family .full`. At each suitable fixed period, the latter supplies convergence of the full mesh sequence; its limit equals the refined-mesh row limit by `tendsto_nhds_unique` after composition with `f.mesh.cofinal`. The period-stage limit is then the one already in `F.room.ordered`. `YM.R2IGoals.fromFunded` calls exactly this argument with `hJ.fullMesh` (`Lean/YM/R2I/Campaign/Accepted.lean` 165). It does not promote `copies` or `corrected` to the full-mesh order.

An `Ordered` receipt is not a diagonal limit. `YM.Extraction.Order.limits` first takes the mesh limit at each suitable fixed period, then the period limit of those mesh-limit values (`Lean/YM/Extraction/Orders.lean`). `YM.Extraction.Order.Ordered` tests smeared Wilson moments, with support inside the suitable fundamental cell (`Lean/YM/Extraction/Limits.lean`). `PointLimits` adds local generic-point information; it is a separate field of `YM.Spec.Seed` (`Lean/YM/Spec/Closed.lean`).

## Conceptual graph and source-graph limit

Proposed mathematical order for the stronger internal endpoint: **PU-15 → PU-16 → PU-17 → PU-18 → PU-19 → PU-27**, with PU-13 feeding PU-16 and PU-20 receiving the separate continued-stress output from PU-19's source neighbourhood. For the public reconstruction clauses, the projected path goes from PU-18 to PU-27 without requiring the specifically PU-19 results; it also retains the derivative-side `covers` input above. This is a proposed mathematical split, not a claim that the current public source proof avoids the larger receipt. PU-18 uses the selected phase; PU-19 applies and strengthens the reconstruction across all characters and proves mixture of boundary distributions. This order is acyclic only after projecting `Spec.Final` and `Broad.refine` into the smaller mathematical interfaces above. For PU-19 there is a standalone source theorem, `YM.EveryPhase.all_characters`, whose only input is a `Final`; for PU-16–PU-18 no independent source theorem for the projection has been identified. The split is an editorial proof obligation, not a Lean refactoring.

The compiled map's source-unit links (including V.3 → II.1) and Lean imports may run forward or backward relative to this exposition. They establish constant reachability or code organisation, not these conceptual arrows. PU-19 must remain distinct from PU-18: `Completed` adds every-character quantification, uniform low-energy/heat estimates, irreducibility, continuity and the unselected integral, beyond the selected `Realizes` statement. A merger is justified only if a reviewed source theorem covers those additions with matched hypotheses. No such citation is currently accepted.

The first independent work can be the PU-15 selected-run/full-mesh statement and issue #6's OS literature comparison; they have disjoint outputs. A PU-16 author can begin the extraction statement once PU-15's family contract is fixed, while a separate PU-17 boundary audit can identify the phase representation hypotheses without claiming the PU-16 theorem. PU-18 should wait for issue #6's verified citation decision and the PU-17 phase contract. PU-19 should wait for the PU-18 selected reconstruction and agree its stress handoff with PU-20. If PU-16's compactness and Euclidean-hierarchy arguments prove independently reviewable, request two new issues with separate paths before assigning authors; do not have both claim `Broad.refine`.

For formal-scaffolding triage, `Extraction.Order.upon` and `Order.retained` preserve an already established limit under composition; `YM.Spec.Final.onward` transports a `Final` along a refinement (`Lean/YM/Extraction/Limits.lean`, `Orders.lean`, `Spec/Closed.lean`). These may be grouped in one mathematical refinement-stability argument. The many table/label conversions in `YangMills.publicReconstruction` (`Lean/HierarchyBridge.lean`) are candidate bridge bookkeeping, but its injectivity, surjectivity and mixture obligations have actual mathematical content and cannot be suppressed as coercions. This classification is provisional pending an independent correspondence review.
