`coverage-inventory.json` partitions every currently included chapter once into

is for dependency closure and review, not for translating all Lean declarations.
It deliberately covers chapters with local agent passes: a conditional local

not assigned to be completed. New integrated chapters must be assigned before
release; external canonical dependencies such as YM-000022 need their own entry.

## Common contract for every coverage package

A worker reads only its assigned chapters, relevant portions of correspondence,
adjacent evidence and current review reports, then the exact Lean declarations
and definitions at any unresolved handoff. Reuse accepted source evidence and
precisely checked literature. Do not redo the entire build or search the whole
source tree. Source revision3456e5e75cf8d4cd558955a5c7638fba2d68f464 is fixed.

For each theorem or coherent proof group, record every mathematical input:
exact quantified statement, constructed objects, normalization and choice order,
producer chapter/label, source declarations and paths, and status of the match.
Distinguish definitions/standard reader prerequisites, applicable checked
references, already proved interfaces needing cross-references, and genuine
missing arguments. Source theorem existence, a helper's name, or a clean axiom
report is not proof that the manuscript explains the argument. Preserve same
history, field quotient, operator, stress sign and extraction filter throughout.

The output is a unique report with an input/output ledger and any definite
findings. Substantive repairs within the assigned chapter files are authorized in the eventual released C scopes. No substantial out-of-scope proof repair: propose a bounded disjoint
follow-up for each genuine missing argument. Small changes are still authored
changes and require renewed independent review; never refresh another reviewer's
fingerprint yourself. Shared integration files and another package's prose are
read-only. At release, each package receives its own issue, claim protocol,
owned report paths and acceptance criteria.

Coverage audits can run in parallel because report outputs are disjoint.
Incoming dependencies may be draft, but a consumer is marked closed only after
the exact producer theorem is available and independently checked. The combined
ledgers must have no unexplained mathematical premise or circular use; separate
review must test the union, not merely count16 completed reports.
